# FeatureZoneModule

Модуль собирает Re-ID gallery для локальных треков, когда контрольная точка bbox попадает в прямоугольную зону. Использует `FeaturesManager.extract_features(image_list)` и `calculate_similarity(...)`.

## Схема зон

Все координаты размечаются на кадре 1280x720. Каждая зона задаётся двумя противоположными углами `p1` и `p2` в `feature_zones.yaml`; отсутствующая зона выключена.

- **Камера 1:** две зоны `LEFT` и `RIGHT`. Проверяется нижняя центральная точка bbox. Зона определяет, у какого шлагбаума появился трек.
- **Камера 2:** две зоны `LEFT` и `RIGHT`. Проверяется центр правой грани bbox. Сторона определяется по зоне, в которую попала эта точка.
- **Камера 3:** одна зона `DEFAULT`. Проверяется центр верхней грани bbox.
- **Камеры 4–9:** не собирают scan-gallery в `FeatureZoneManager`; при этом они остаются частью общего трекинга, а общая RuntimeReID-идентификация работает на камерах 2–9. `EntrySessionManager` допускает привязку journey-track на камерах 1–9, но scan-gallery поддерживает только камеры 1–3.

На камерах 1 и 2 обе зоны проверяются автоматически, не нужно заранее переключать активную сторону для обработки. Переключение `1`/`2` в отладчике выбирает только зону, которую редактируют.

## Захват признаков

- Зона — это триггер выбора/активации локального трека, а не граница, внутри которой разрешён сбор признаков.
- После активации трек продолжает собирать признаки и за пределами полигона, пока трек остаётся видимым и вызывающий код не завершит его галерею.
- Проверка триггера выполняется при каждом вызове `process_frame`; `sample_every_n_frames` ограничивает только извлечение признаков, а не обнаружение входа в зону.
- На каждом кадре выборка выполняется для всех видимых активированных треков камеры. Несколько автомобилей могут обрабатываться одним batch-вызовом; результаты раскладываются обратно по своим `track_id`.
- Кропы оригиналов и горизонтальных отражений отправляются в одном batch-вызове экстрактора.
- Сравнивается только новый ORIGINAL embedding с последним принятым ORIGINAL. Если cosine similarity >= 0.90, пара отклоняется как почти дубликат; иначе original и flip добавляются в разные массивы.
- Вектора L2-нормализуются. Галереи разделены по `(camera_id, local_track_id)`; у галереи сохраняется `zone_profile`.

### Если локальный track_id поменялся

Зона проверяется по каждому текущему bbox независимо от того, был ли такой track_id раньше. Поэтому новый ID, появившийся внутри зоны, тоже начнёт собирать признаки. Однако это будет отдельная локальная галерея: модуль намеренно не объединяет автоматически два ID только из-за близости во времени/пространстве — такое объединение может склеить соседние машины. Сопоставление и возможное объединение галерей нужно делать отдельным этапом по Re-ID и контексту трека.

## Жизненный цикл и очередь въезда

При событии EXIT вызывающий код может закрыть локальную галерею через `end_tracks_on_exit(camera_id, events)`. На остановке потока — `close_all()`. Сам модуль не пишет в БД.

Для preproduction добавлен `EntrySessionManager`:

- Триггер камеры 1 создаёт сессию с монотонным `entry_order`; повторное срабатывание для того же ещё известного локального трека не создаёт дубликат.
- Новая машина может создать следующую сессию, пока предыдущая всё ещё собирает признаки. Триггеры не блокируются.
- Галереи остаются отдельными по локальным трекам. Очередь не объединяет треки сама по себе.
- Камерные треки 2/3 привязываются к сессии явно через `bind_track` либо по FIFO через `bind_next_in_order(..., confirmed_registered_entry=True)`. FIFO вызывается только для подтверждённого участника въезда, а не для каждого обнаруженного автомобиля: посторонняя машина не должна занимать позицию.
- Потеря привязанного трека на камере 2 завершает соответствующую общую сессию через `finish_on_camera2_track_lost`. Вызывающий код должен сначала определить реальную потерю трека с grace period, чтобы кратковременный пропуск детекции не закрыл сессию.
- OCR должен выполняться независимо: его результат или задержка не являются условием завершения сбора признаков.
- Камеры 4–9 не передаются в `FeatureZoneManager`, но могут иметь journey-track bindings в `EntrySessionManager` и участвуют в общей RuntimeReID-идентификации. Это не делает их камерами scan-gallery: галереи сканирования по-прежнему ограничены камерами 1–3.

Важно: `EntrySessionManager` используется `run_main_controller.py` для координации сессий и привязок локальных треков. Сам менеджер не запускает видеопотоки и не выполняет OCR/DB-запросы; это координирует controller.

Пример:

    from FeatureZoneModule import FeatureZoneManager
    from FeaturesModule.FeaturesManager import FeaturesManager
    from Config import Config

    features = FeaturesManager(Config.OSNET_MODEL_PATH)
    zones = FeatureZoneManager(features, "feature_zones.yaml")
    accepted = zones.process_frame(
        camera_id=2,
        frame_id=frame_id,
        frame=frame,
        tracks=list(zip(track_ids, boxes)),
    )

## Запуск отладчика из PyCharm

Откройте и запустите зелёной кнопкой Run файл
[`run_feature_zone_debug.py`](https://github.com/a-koptev/for-claude/blob/feature-candidate-search-v1/run_feature_zone_debug.py).
Аргументы командной строки не нужны. Если `VIDEO_SOURCE` не найден, появится диалог выбора видео. Скрипт не подключается к БД.

### Клавиши

Отладчик показывает зоны в режиме просмотра — он не рисует и не сохраняет разметку.
- **1 / 2** — выбрать/подсветить профиль LEFT / RIGHT на камерах 1 и 2.
- **D** — выбрать профиль DEFAULT на камере 3.
- **Space** — пауза; **Q** или **Esc** — выход.

Для изменения разметки вручную отредактируйте координаты `p1` и `p2` в `feature_zones.yaml`, затем перезапустите отладчик. Для камер 1 и 2 задаются два прямоугольника LEFT/RIGHT; для камеры 3 — прямоугольник DEFAULT.

Отладчик показывает bbox и контрольную точку только для камер 1–3: камера 1 — нижняя середина, камера 2 — центр правой грани, камера 3 — центр верхней грани. Камеры 4–9 не размечаются и не собирают scan-gallery этим модулем, но остаются в общей tracking/RuntimeReID-схеме. Линии переходов из topology.yaml относятся к межкамерным переходам и не являются зонами захвата.

Логи: `feature_zone_debug.log`; сводка: `feature_zone_debug_report.json`.

## Проверки

Запустить `python -m unittest discover -s tests -p test_feature_zone.py`. Тесты используют fake extractor и не требуют весов OSNet. Нужны OpenCV, NumPy и PyYAML.


## Запуск сценария с триггером

Для интегрированного девятикамерного controller запустите `python run_main_controller.py`: он координирует scan-gallery на камерах 1–3, OCR на камере 1, lane-constrained FIFO на участке камера 1→2, FIFO-handoff на камере 3 и topology-gated RuntimeReID на остальных поддерживаемых переходах. RuntimeReID использует камеры 2–9 и исключает только конкретные track'и, принадлежащие активной scan-сессии на камерах 2/3. По умолчанию `PARKING_DB_ENABLED=true`, поэтому controller пытается подключить PostgreSQL и выполняет реальные DB-операции; для запуска без БД задайте `PARKING_DB_ENABLED=false`.

Сценарий `python run_feature_capture.py`, описанный в [README_FEATURE_CAPTURE_RUN.md](README_FEATURE_CAPTURE_RUN.md), — отдельный облегчённый runner для проверки сбора признаков; не путайте его с интегрированным `run_main_controller.py`. Пути всех камер задаются через `PARKING_CAMERA_1_VIDEO` … `PARKING_CAMERA_9_VIDEO` или `Config.CAMERA_VIDEO_PATHS`.
